Como publicar o catálogo

O site fica na internet. O painel fica no seu Mac. Você cadastra as peças no painel e clica em Publicar — o site se atualiza sozinho.

Instalação

Uma vez só, na primeira vez. Leva uns dois minutos.

Abra o instalador

Salve o arquivo instalar.command na sua Área de Trabalho e dê dois cliques nele.

O Mac vai desconfiar do arquivo. Como ele veio da internet, o macOS bloqueia na primeira tentativa. Em vez de dois cliques, clique com o botão direito sobre o arquivo, escolha Abrir, e confirme Abrir na janela que aparecer. Isso só é necessário uma vez.

Deixe ele trabalhar

O instalador confere se o Mac tem o que precisa, baixa o painel para uma pasta chamada DivinaLolla na sua pasta de usuário, e prepara tudo.

Se faltar o Python, ele avisa e manda o endereço para baixar. Se faltar as ferramentas da Apple, ele abre a janela de instalação. Nos dois casos: instale o que ele pediu e rode o instalador de novo.

Mande a chave para o Rafael

No final, o instalador mostra um texto comprido começando com ssh-ed25519. Essa é a chave que identifica o seu Mac.

Copie o texto inteiro e mande para o Rafael. Ele libera o acesso e avisa quando estiver pronto.

Não precisa esperar para começar. O painel já funciona sem a liberação: você pode cadastrar as peças e ver como o site vai ficar. Só o botão Publicar fica esperando.

O dia a dia

Abra o painel

Dois cliques em iniciar.command, dentro da pasta DivinaLolla. O navegador abre sozinho no painel.

Uma janela preta de texto fica aberta atrás — é o painel funcionando. Deixe ela aberta enquanto estiver trabalhando; para encerrar, feche a janela.

Cadastre as peças

Preencha nome, descrição, preço e categoria — Brincos, Colares, Anéis — e escolha a foto. A categoria nova aparece sozinha no site quando você cadastra a primeira peça dela.

O que você salva já vale no site local na hora. Dá para conferir tudo antes de mandar para a internet.

Clique em Publicar

É o que manda tudo para o site na internet. Depois de aparecer a confirmação, o site leva de um a dois minutos para mostrar as novidades.

Esse mesmo botão também traz o que a outra pessoa publicou. Então, se quiser só conferir se tem coisa nova, clique em Publicar: se não houver nada seu para enviar, ele avisa e atualiza o seu catálogo.

Quando duas pessoas mexem juntas

Vocês dois publicam no mesmo catálogo, cada um do seu Mac. O painel junta as duas versões sozinho — mas vale saber quem ganha em cada situação.

Situação O que acontece
Cada um cadastra peças diferentes As duas entram no site. Nada se perde.
Os dois editam a mesma peça Vale a versão de quem clicou em Publicar por último.
Um apaga a peça, o outro edita A peça é apagada. A exclusão vence.
Um publica enquanto o outro cadastra Sem problema. Ao publicar, o painel busca o que mudou e junta antes de enviar.
Combinem por fora quem cuida do quê. O painel resolve a mecânica, mas não sabe qual das duas versões de um mesmo colar é a certa. Editar peças diferentes evita a dúvida.

Para o Rafael: liberar um Mac

Quando a chave chegar. Feito uma vez por máquina.

Pelo site do GitHub

No repositório, vá em Settings → Deploy keys → Add deploy key. Dê um título que identifique a máquina, cole a chave recebida e — o passo que importa — marque Allow write access. Sem isso a pessoa consegue ler, mas não publicar.

Pelo terminal

Salve a chave recebida num arquivo e rode:

gh repo deploy-key add chave.pub \
  --repo rafaelcsouza1/divina-lolla \
  --allow-write --title "Mac da Ana"

Para conferir ou remover depois: gh repo deploy-key list e gh repo deploy-key delete. A chave vale só para este repositório e pode ser revogada a qualquer momento, sem afetar mais nada.

Chave adicionada pelo terminal fica presa ao seu login do GitHub CLI. Se você desautorizar o GitHub CLI da sua conta, as chaves criadas por ele saem junto e a outra máquina para de publicar. Pelo site do GitHub isso não acontece.
